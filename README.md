# Boardcast · 邻间

面向局域网的文件和文件夹传输。Windows 原生界面、独立网络后台、设备备注与信任，以及可选的本机 CLI / MCP 扩展。

**项目状态：Windows 0.2.8，新增已许可网段发现、遗忘和多设备分享。** 本次更新日期为 2026-10-10；构建、测试和实际覆盖范围见 [验证记录](docs/verification.md)。macOS 是独立 Swift 实现，本次同步网段功能源码，由 Mac 环境构建与验收，交付状态见 [macOS 说明](platforms/macos/README.md)。

**Windows 正式分发：** [0.2.8 完整签名包](dist/Boardcast-win-x64-0.2.8.zip) 与 [SHA-256 校验文件](dist/Boardcast-win-x64-0.2.8.zip.sha256)，沿用原有发行公钥。大文件使用 Git LFS，克隆前请安装 [Git LFS](https://git-lfs.com/)。分发目录说明见 [dist/README.md](dist/README.md)；签名与密钥保管见 [签名发行说明](docs/signed-release.md)。

Windows 0.2.8 签名发行包在显式 IP 连接成功后学习网段并发现设备，支持在设置中遗忘，以及向选定设备分享网段，由接收方明确接受。仅探测已许可的私有 IPv4 网段，不增加 NAT 映射或穿透；说明见 [网段发现与分享](docs/subnet-discovery.md)。保留自适应文件行、单行设备列表和按需文件操作。macOS 后续设计见 [产品与界面方案](docs/macos-design.md)，本地编写、构建与验收见 [Mac 开发交接](platforms/macos/DEVELOPMENT.md)。

Android 手机和平板目前仅完成设计：[界面与操作方案](docs/android-design.md)、[文件与目录存储规范](docs/android-storage-design.md)。尚未创建 Android 工程或安装包。

## 使用

整包解压后运行 **Boardcast.exe**。接收端也运行邻间，双方连接同一局域网：

1. 清单为空时，点击中间箭头或下方添加提示，选择“文件 / 文件夹”；已有内容时使用标题行的“添加”。也可直接拖入文件与文件夹，两者可加入同一待发送清单。
2. 可选：选中文件夹后点击“排除…”，选择不发送的子文件、子文件夹，或填写相对路径（每行一项）。目录连同子项排除；留空发送全部。需要附言时展开“说明”。
3. 在“附近设备”中勾选一台或多台接收设备，再点击发送。对方查看清单、说明和接收目录，接受或拒绝；每台设备的进度与取消操作相互独立。
4. 右键设备打开“设备详情”，核对指纹、填写本机备注。自动接收需要设备许可和匹配规则；在“设置 → 接收规则”中配置。

导航默认收起，点击左上角按钮可展开，程序会记住这个选择。主入口为发送、传输记录和底部设置。主区直接呈现“待发送”和“附近设备”；拖动中间分隔条可调整宽度。连接状态位于左下角本机信息区，导航收起时显示状态圆点，展开时显示状态文字。

附近设备标题、分组选择、显示/总设备统计和刷新共用一行。每台设备仅占一行：平台图标、设备名、必要的状态图标和版本标记。可提供适用新版本的设备显示蓝色可点击版本气泡，其他版本使用灰色标记，不再另外显示“有更新”；系统、分组、信任状态、地址和完整版本保留在悬停提示与设备详情。文件名、大小与文件数量能完整放下时使用单行；否则保留两行，随窗口宽度和统计结果自动调整，首页与展开清单采用同一布局。待发送标题行集中“添加”和“清空”，选中内容后才显示移除或文件夹排除操作；文件筛选无结果时，点击中间提示即可清除筛选。文件区与设备区保持稳定的基础空间，随窗口伸缩；增删少量内容不会改变外框高度，说明展开只调整内部列表空间。大量内容使用虚拟化滚动清单，并提供筛选和“展开清单”。筛选只改变显示，发送仍使用完整待发送内容；设备的文字搜索也保留已选对象，选中数量与名称会继续显示，可用“清除选择”取消全部接收对象。分组筛选则会清除被隐藏设备的选择，避免向已隐藏的组发送。

添加文件夹后，列表先显示“正在统计…”，再异步显示大小和文件数。按 CPU 数量安排 1–4 个目录并行扫描，其余异步排队；只读取元数据，不读取文件正文。移除项目会取消该目录的扫描或排队，重新添加或修改排除项会重新统计。链接或无法读取的项目会标明未统计，不把部分结果当成完整大小；统计、发送清单和 CLI 摘要均按排除后的内容计算，发送时仍会重新验证内容。

### 设置

设置分为常规、接收规则、设备与信任、扩展、关于与更新。各页使用统一的分组列表和行内操作。设备名称、接收文件夹和允许接收需点击“保存更改”；登录启动开关立即生效。本机完整指纹、复制入口、端口和最近诊断位于常规页的“设备信息与网络诊断”中。

接收规则的“编辑”直接显示，上移和删除在该规则的“···”菜单中。设备与工具名称过长时可悬停查看，长列表可滚动至末尾。

### 设备分组

每个用户分别保存本机分组、对其他设备的个人分组和附近列表筛选。默认按设备名称的前缀归组：以 `-`、`_`、`.` 或空白分隔，取第一个非空片段，例如 `设计部-张三`、`设计部_李四` 都属于“设计部”；没有分隔符时使用完整名称。大小写不影响匹配。

在“设置 → 常规”填写“我的分组”，保存后会立即向附近设备发布；留空恢复名称前缀规则。设备详情中的个人分组只对当前用户生效，不会修改对方设置。显示优先级为：个人分组 → 对方自定义分组 → 对方原设备名的前缀；设备备注不参与自动分组。自定义分组最多 80 个字符。

附近设备提供“全部 / 与我同组 / 指定分组”，指定分组支持多选，设置会保存并在下次启动恢复。首次安装或旧版升级默认显示全部；想默认只看同组设备，选择“与我同组”即可。修改自己的组名后，同组范围随之更新；想恢复时选择“全部”。指定分组未勾选任何组时显示空列表，并提供恢复全部的入口。

筛选仅减少列表干扰，不是访问控制。被隐藏的设备仍可发起接收请求；已有信任、接收规则、正在进行的传输及“关于与更新”中的来源发现不变。没有分组字段的旧设备按其名称自动归组。

### 局域网连接与发现

启动、连接和系统网络恢复时主动发现设备；设备上线后自动刷新列表，仍可点击“刷新”。点击左下角本机信息区的连接状态，让邻间广播下线；断开后再次点击重新广播上线。这只控制邻间的发现与新传输，不关闭系统网络。

断开连接会停止新的发送和接收，取消尚未开始或等待批准的发送；已经接受的传输可继续完成。接收开关与局域网连接相互独立。广播下线信息只提供未认证的离开提示，不能据此建立或删除设备信任，详见 [多设备发送与连接](docs/multi-recipient-transfer.md)。

多设备发送复用一份文件清单，每个目标使用独立加密连接，全局最多四路并发，其他目标排队。新版设备通过共用分块引擎支持传输恢复，并在符合条件的多设备大文件传输中尝试授权 P2P；旧设备继续使用原有加密流。慢速、缺块或离线来源会回退原发送方。实际速度取决于网络和磁盘，不承诺固定加速比例；见 [多设备传输说明](docs/multi-recipient-transfer.md)。

### 网段发现与分享

Windows 和 macOS 支持通过 IP 连接学习网段，并自动发现该网段中的邻间设备。Windows 常规设置、Mac 网段发现设置可遗忘已保存网段；附近设备的“分享网段”可向一台或多台设备发送本机接口或已保存网段，对方明确接受后才启用发现。不同 AP 之间仍须允许单播 IP 通信。范围、兼容与验证边界见 [网段发现与分享](docs/subnet-discovery.md)。

### 局域网版本更新

单行设备项以平台图标和设备名称为主，灰色版本标记表示对端当前运行版本；可提供适用新版本的设备显示蓝色更新目标版本气泡，帮助提示同时说明运行版本。点击蓝色气泡进入更新设置，查看目标版本、来源和下载状态，不自动下载。首页推荐来源仍优先选择适合当前系统、架构和发布渠道的最高较新版本；多个可用设备可显示各自的蓝色版本入口。更新设置按版本列出可用来源，可以选某个兼容的较新版本；右键设备仍可置顶或选择它提供的版本。手动来源仍受兼容、版本和签名检查限制，不支持降级。

后台只发现版本，不自动下载，旧配置中曾启用的自动下载也会关闭。明确选择版本后，将更新包作为文件使用同一套分块、校验和恢复机制传输；校验发布签名、完整包和每个文件后等待安装。中断后选择相同版本即可继续，后台重启会重新验证并恢复待安装状态。设备身份与发布者身份分开验证：本机发行包固定的受信公钥决定哪些更新可以执行，不接受附近设备临时提供的未知公钥。

安装必须等待所有传输和待确认请求结束，再由用户点击“重启并更新”。安装器等待当前界面与后台退出，切换程序目录，启动检查失败时按安全条件恢复旧版。设置、设备身份、规则和接收目录保存在程序目录之外。

当前默认开发包没有正式发行签名，更新安装保持禁用；不能仅因另一台设备版本更高就执行其程序。正式签名发布准备、更新流程和限制见 [局域网版本更新](docs/peer-updates.md)。发行签名与 Windows Authenticode / SmartScreen 是不同机制，本项目尚未完成正式签名包的干净机器验收。

### 托盘与后台

点击窗口关闭按钮或按 Alt+F4 收起到系统托盘，传输继续。双击托盘图标或右键“打开 Boardcast”恢复窗口；托盘“退出”或“设置 → 常规 → 退出程序”停止当前传输、文件夹扫描和本机 CLI 摘要任务，并等待后台结束后完整退出。未完成发送会保留恢复记录，重启后由用户继续。

隐藏到托盘时停止界面状态轮询；需要确认的来件会唤回传输记录页。登录启动可在设置开启，启用后直接进入托盘。电脑清醒且后台运行时才会响应发现；广播不能启动已停止的后台或唤醒睡眠电脑。--no-ui / --service 模式不自动显示来件窗口。默认以登录用户身份运行，不把网络程序默认安装成 LocalSystem 服务。

### 接收规则

规则从上到下匹配。条件包括设备、文件/文件夹、后缀、顶层文件夹名称模式和总大小，目标目录可分别指定。所有内容都满足条件才匹配，不因文件夹内某个文件符合后缀便接受整个文件夹。

自动接收必须同时满足：身份指纹一致、设备已信任、设备允许自动接收、命中规则允许自动接收。没有匹配规则时询问。详情见 [规则与扩展](docs/rules-and-integrations.md)。

### 接收保存与取消

自动接收规则的目录或手动确认的目录就是最终保存位置。散文件直接放入该目录，文件夹保留发送方的结构，不再增加长名字的任务目录。遇到同名内容时自动追加序号，例如 `报告 (1).pdf` 或 `资料 (1)`；已有内容不会被覆盖。

每个文件接收完整、通过校验并成功保存后立即保留，不必等待整批传输结束。接收目录不再留下校验 JSON 或分块副本；恢复记录在应用数据目录内部保存。传输记录显示已保存文件数，部分完成后也可以打开接收目录。

主动取消会停止接收和写入，关闭句柄后清理本次任务未完成或校验失败的内容，并保留已保存的文件。网络中断与退出程序保留有效分块，发送方继续同一任务时会重新校验恢复；失败的接收可用“清理未完成内容”放弃恢复。删除受占用影响时记录待清理，后台启动和后续接收会重试。清理不删除用户原有目录。

### 只在局域网内

核心没有云账号、公网中继、互联网发现、NAT 穿透或遥测。自动发现使用 IPv4 子网广播（TTL 1）；广播不可用时可按私网 IP 连接。Windows 按系统路由访问允许的私有地址，私网 VPN 或跨 VLAN 仍可能可达，不保证物理同一网段；详见验证记录。访客 Wi-Fi 的客户端隔离和防火墙仍可能阻止通信。

Windows 防火墙弹窗请选择专用网络。发行包中的 Configure-Firewall.ps1 是可选管理员脚本，仅放行该后台程序在专用网络/本地子网的 TCP（文件传输及动态更新端口）和指定 UDP 发现端口。软件不会自动关闭防火墙。

### 内容与身份保护

- 双向 TLS 传输，设备身份使用持久证书指纹；UDP 发现信息本身不构成身份认证。
- 首次信任请在对方设置页核对完整指纹，对方改名不会改变本机备注。
- 新设备使用有界分块读写和 SHA-256 校验；同批批准的设备才可互供分块。旧设备保留原有流式传输。
- 拒绝危险路径、重复路径、符号链接/重解析点和跨平台不安全文件名。
- 接收写入暂存区，校验通过后提交，不覆盖已存在的同名内容。
- 不自动打开或执行收到的文件，不依据远端摘要执行命令。

发送过程中可以在“传输记录”暂停，暂停或失败后点击“继续传输”；显式取消会移除恢复入口。后台重启保留近 7 天的未完成发送记录。恢复时重新检查源文件和已收分块，内容变化不会混入旧数据；继续发送仍遵循对方接收规则。

## 可选扩展

同包的 boardcast-cli.exe 提供脚本接口和 MCP stdio server。LLM CLI 可发现设备、发送文件、检查进度和处理接收请求；多设备发送与局域网上线状态另有 IPC 入口，暂停和继续传输也可通过 CLI / MCP 操作。

反向调用 CLI 时，在发送页明确触发，将元数据清单写入已配置程序的标准输入，输出回到说明框等待检查。飞书/云 LLM 是用户自行配置的外部工具，不属于局域网文件传输通道，也不是必装依赖。见 [集成说明](integrations/README.md)。

## 开发与构建

以下命令在完整源码目录执行，发行 ZIP 不包含开发工程。

### 依赖环境（不入库）

| 用途 | 依赖 | 是否进入仓库 |
|------|------|----------------|
| Windows 构建 / 测试 / 本地发布 | [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) | 否（本机或 CI 安装） |
| 终端用户运行正式 ZIP | 无（自包含） | ZIP 在 `dist/`，经 Git LFS |
| NuGet / npm / Electron / WebView | 无 | — |
| macOS 独立客户端 | macOS 13+、Swift / Xcode | 否；见 [platforms/macos](platforms/macos/README.md) |
| 可选 LLM / 飞书 CLI | 用户自行安装 | 否；见 [integrations](integrations/README.md) |

`scripts/Test.ps1` 与 `scripts/Publish-Windows.ps1` 会调用 `scripts/Require-DotNetSdk.ps1`，在缺少合适 SDK 时失败并给出安装链接。本地发布默认写入被忽略的 `artifacts/`；正式对外包只提交 `dist/` 下的 ZIP 与校验文件，不解压后的 runtime 目录。

~~~powershell
dotnet build Boardcast.slnx
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Publish-Windows.ps1
~~~

默认打包为自带运行时的 ZIP，接收用户无需安装 .NET。界面、daemon、CLI 和 updater 共享运行时文件；整包复制，不要只取一个 EXE。ARM64 可用 -Runtime win-arm64 构建，未经 ARM64 实机验证时按预览版本处理。默认发布不含受信发行签名；签名发行使用 Publish-Windows.ps1 的版本与签名参数，详情见 [更新发布准备](docs/peer-updates.md)。

开发运行：

~~~powershell
dotnet run --project src/Boardcast.Daemon -- --no-ui
dotnet run --project src/Boardcast.Windows
~~~

独立布局回归不打开主窗口，也不启动 daemon 或托盘：

~~~powershell
dotnet run --project tests/Boardcast.LayoutTests -c Release -- --render-preview
~~~

默认设置、身份和界面偏好位于 %LOCALAPPDATA%\Boardcast。测试支持独立 --data-dir，不要分享身份私钥文件。
