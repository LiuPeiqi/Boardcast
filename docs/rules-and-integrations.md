# 接收规则与本机扩展

## 接收决策

自动接收必须同时满足：

1. 接收服务启用。
2. 对端 TLS 证书的 SHA-256 指纹与清单声明一致；身份依赖证书，不依赖名称、备注、IP 或广播中的自报字段。
3. 已知设备恰好存在一条该指纹记录，并同时开启“信任”和“自动接收”。
4. 第一条匹配本次完整清单的启用规则开启自动接收。

未匹配规则、重复身份配置、设备未信任或规则要求确认，都转入手动确认。恶意路径、非法清单及身份不一致直接拒绝。首条匹配规则决定接收目录；后面的规则不再参与。这样可在通用自动规则前插入更严格的手动规则。备注仅保存在本机，不会改变对端身份。

接收暂停由守护进程拒绝新请求。策略模块返回“非自动”只是决策结果，调用方不能把它当成暂停期间继续创建待接收任务的授权。

## 一条规则匹配整个批次

- 空设备指纹表示所有设备；仍须通过设备级信任与自动接收检查。
- Scope=files 仅接受顶层单文件批次；清单出现目录或带父路径的文件即不匹配。
- Scope=folders 要求所有顶层项目都是目录。显式空目录和从子路径推导的目录均支持。
- Scope=any 允许混合项目。
- FolderNamePattern 只提供 * 和 ? 通配符，不执行正则或脚本；不区分大小写。每个顶层目录都须匹配，混入顶层单文件则不匹配。空模式不限制目录名。
- Extensions 是最终扩展名白名单，不区分大小写，可写 pdf 或 .pdf。所有非目录文件均须匹配；a.pdf.exe 不匹配 .pdf。空白名单表示不限制类型；它不做内容识别或杀毒。仅含空目录时后缀条件自然满足。
- MaxBytes=0 表示本条规则不另设上限；仍受全局 MaxTransferBytes 限制。负值不匹配。
- Destination 为空时使用全局接收目录；非空必须是本机绝对目录。网络共享、链接目录、重解析点不允许作为接收目标。
- 一次发送使用一条规则和一个接收根目录，不会为了让其中一部分文件自动接收而拆分批次。

示例规则：来自已信任工作电脑的 invoice-* 文件夹，只包含 PDF、总大小不超过 200 MiB 时自动保存到本机发票目录；其他发送仍需确认。

```json
{
  "name": "工作电脑的发票",
  "enabled": true,
  "deviceFingerprint": "替换为实际的64位十六进制证书指纹",
  "scope": "folders",
  "extensions": [".pdf"],
  "folderNamePattern": "invoice-*",
  "maxBytes": 209715200,
  "destination": "D:\\Documents\\Invoices",
  "autoAccept": true
}
```

## 文件系统边界

清单校验拒绝绝对路径、..、空路径段、NTFS ADS、Windows 保留设备名、结尾空格/点、非法字符，以及大小写或 Unicode 规范化后冲突的路径。目录大小必须为 0，文件大小非负；总大小使用溢出检查。条目数受本机配置及 100000 的硬上限约束。文件不能成为其他条目的父目录，避免文件与文件夹互相覆盖。

ResolveUnderRoot 保留相对层级，并对接收根、其祖先和目标现存路径检查重解析点。该检查不是针对恶意本机用户的完整文件系统沙箱：并发替换路径存在检查和使用之间的竞争。传输层应使用仅当前用户可写的独立临时目录、排他新建文件，并在提交前重新检查；不可将“路径字符串已校验”理解为允许覆盖已有文件。

## 扩展的输入与权限

核心发现和传输仅在局域网进行，不访问公网，不需要账号、云服务、LLM、飞书或任何外部 CLI。下面的扩展完全可选，需在本机显式配置并主动调用。没有“收到文件就执行对方命令”的协议能力。

IntegrationRunner 有两个调用入口：

```csharp
RunAsync(profile, manifest, cancellationToken);
RunAsync(profile, manifest, selectedLocalFiles, cancellationToken);
```

扩展必须启用、指定已有可执行文件的绝对路径。Windows 直接执行 .exe；参数逐项通过 ArgumentList 传入，UseShellExecute=false，不拼接 shell 命令，不把文件名、摘要或对端字段拼入参数。

stdin 输入为版本化 JSON：schema、untrustedMetadata、transferId、senderName、totalBytes、entries（relativePath、size、isDirectory）。默认不读取文件正文、不提供本机绝对路径、不把对端 Summary 转交扩展。文件名与设备名仍是不可信数据，扩展应将其视为数据，不能当成模型指令。

只有本机配置 IncludeLocalPaths=true 且调用方提供与清单文件一一对应的已选文件映射时，输入才增加 localFiles：[{relativePath, localPath}]。映射必须指向仍存在的本机绝对文件；目录、远端路径、UNC 共享、缺失/额外条目都不接受。核心不会替用户自动读取全文；本机选择的 CLI 可按自身权限读取这些文件进行内容分析。用户应明确理解配置该选项意味着允许该本机 CLI 访问所选文件。

超时范围为 1–300 秒，默认 30 秒；超时或取消请求终止进程树。清单输入最大 1 MiB，元数据最多 10000 项；标准输出与错误输出持续排空但只保留有限缓冲，最终 UTF-8 输出合计不超过 16 KiB。输出只作为文字结果，绝不作为 shell、接收规则或自动执行指令。

这是进程适配器，不是权限沙箱。可执行文件拥有当前本机用户权限；系统权限、网络访问与 LLM 提示词安全由用户所选 CLI 自身控制。用户主动配置云端 LLM 或 Lark CLI 可能使所选数据外发，这属于明确配置的外部动作，不是 LAN 核心传输功能。不要把云端集成作为默认后台任务或必装依赖。

## 验证

无 NuGet 控制台回归测试位于 tests/Boardcast.PolicyTests，覆盖身份冒充、规则顺序、混合文件批次、目录分类、容量、路径冲突和重解析点，并实际启动测试子进程验证 JSON 数据边界、参数字面值、UTF-8 输出上限和超时。
