# Boardcast Android 文件与目录保存设计

Android 手机和平板通过系统文件选择器授权内容与保存位置，传输文件字节、完整相对目录和空目录。收到的文件逐个校验后保存到用户选定的本地目录；取消保留已经保存的文件，未完成内容与任务记录由应用私有数据管理。

本方案为 2026 年 10 月 10 日的设计目标，以 Windows 0.2.7、[Mac 产品设计](macos-design.md)、[局域网协议](protocol.md)和[接收规则](rules-and-integrations.md)为基线。Android 客户端尚未实现；手机和平板界面见 [Android 产品设计](android-design.md)。以下能力、内部目录与验收条件均不表示已有 Android 源码或测试结果。

## 系统授权与内容位置

Storage Access Framework 以下简称 SAF。它以 URI 授权访问系统选择器中的文件和目录，提供者可能对应本地存储、移动卷或云服务。URI 和 document ID 是访问标识，不能拆成物理路径，也不能靠字符串拼接子文件路径。界面使用提供者名称、卷名及可核查的目录层级展示位置；无法取得物理路径时不虚构 `/storage/...`。[Android SAF](https://developer.android.com/training/data-storage/shared/documents-files)、[Document ID](https://developer.android.com/reference/android/provider/DocumentsContract.Document#COLUMN_DOCUMENT_ID)

发送源、协议相对路径和接收目的地分别保存。源 URI 仅在本机使用；offer 只携带相对路径、类型和大小，不传 URI、提供者内部标识或手机绝对路径。接收目的地保存为用户授权 tree URI，并绑定提供者和卷身份；网络端不能选择本机 URI 或系统目录。

仅持久保留系统实际返回且允许保留的读写授权。重启后、内容准备前、接收批准后都重新核实；文档移动或删除可能使已持久化授权失效。撤销、卷离线和提供者不可用分别呈现为“需要重新授权”“存储设备不可用”或“位置无法访问”。重新选择同名目录不自动接管旧任务。[持久 URI 权限](https://developer.android.com/training/data-storage/shared/documents-files#persist-permissions)

## 添加文件和文件夹

“添加”提供“文件”和“文件夹”两个入口。文件使用系统 `ACTION_OPEN_DOCUMENT` 并支持系统多选；文件夹使用 `ACTION_OPEN_DOCUMENT_TREE`，每次授权一个目录树，可多次加入草稿。两者进入同一待发送清单，不要求 Android 选择器像 Mac 面板一样混选。分享入口的临时 URI 先加入草稿并检查授权，选择设备并明确发送后才创建任务。[文件选择](https://developer.android.com/training/data-storage/shared/documents-files#open-file)、[目录树选择](https://developer.android.com/training/data-storage/shared/documents-files#grant-access-directory)

首版只发送可打开为原始字节的文件与可完整枚举的普通目录。虚拟文档没有所声明 MIME 类型的原始字节表示，不静默转换后当作原文件发送；用户需先在源应用导出普通文件。[虚拟文档](https://developer.android.com/reference/android/provider/DocumentsContract.Document#FLAG_VIRTUAL_DOCUMENT)

草稿保存每个顶层项目的源标识、显示名、类型、授权状态和排除集合。移除项目只改草稿，不删除源文档。释放持久授权前检查其他草稿和活动任务是否仍在使用，不能连带中断它们。

## 顶层名称与重复选择

选中的文件夹本身成为发送顶层目录。例如选择“项目资料”，就发送 `项目资料/…`；单独选择其中一个文件时，以该文件名作为独立顶层项，不附带未授权的祖先目录。

顶层名称来自提供者的显示名，经跨平台检查后固定到任务清单。名称缺失、含分隔符或不合法时，要求用户明确设置合法发送名称或重新选择，不悄悄截断、替换字符或拿 document ID 当文件名。发送名称只改变接收相对名称，不重命名源文件。

- 同一提供者的同一 document ID 被重复添加时合并，并提示“已在清单中”；不能仅凭 URI 字符串不同就认为内容不同。
- 已选目录包含另选的同一子项时，确认可核查父子关系后去掉独立重复项，并提示其已包含在哪个目录；无法证明时不按名字猜测。
- 不同来源具有同一顶层名时，在草稿中确认各自发送名称，例如 `资料` 与 `资料 (1)`，再生成清单。这与接收目录中已有内容的重名不同。
- 枚举遇到循环、同一文档在多条目录分支出现或无法确认归属时停止准备，显示条目，不把图结构任意展开成普通目录，不递归到授权树之外。

提供者允许同一文档出现在多个父目录，所以稳定 ID 与展示层级都要检查；仅保存名称不足以判断重复或归属。[Document ID 约定](https://developer.android.com/reference/android/provider/DocumentsContract.Document#COLUMN_DOCUMENT_ID)

## 目录结构与排除

发送草稿选择“项目资料”文件夹和散文件 `说明.txt`，接收位置为“邻间收件”时，应保留以下投影，不平铺子文件。

```text
邻间收件
├── 项目资料
│   ├── 方案.pdf
│   ├── 图片
│   │   └── 首页.png
│   └── 待补充
│       └── 空目录
└── 说明.txt
```

清单显式包含 `项目资料`、`项目资料/图片`、`项目资料/待补充`、`项目资料/待补充/空目录` 等目录条目。目录大小为零，仍有创建、名称检查与保存结果；零字节文件保持文件类型，不与空目录混同。

统计分别显示顶层项目、文件、文件夹、空目录及字节数，空目录包含排除后已经为空的保留目录。“0 B · 2 个空文件夹”可以发送，按钮依据条目而非字节大于零判断。枚举未完成或大小未知时显示“正在统计”或“大小待确认”，不把未知值当零。

排除编辑仅浏览所选授权树，以顶层目录为基准保存明确子项相对路径。排除 `图片` 同时排除全部子项；排除 `图片/首页.png` 只排除该文件，仍保留未排除的目录。空集合发送全部；不引入 glob、正则或绝对路径。统计、清单与摘要共用排除语义。[现有排除约束](protocol.md#resource-limits-and-local-control)

不可读、枚举不完整、权限失效或非法名称使草稿显示“无法完整发送”，列出相对位置并阻止该批发送。用户可重新授权，或明确加入排除后重新准备；不得跳过失败项后声称发送整个文件夹。已主动排除项不进入后续枚举。移除、重加、改排除会取消旧扫描，旧结果不得回写。

## 源内容准备与稳定性

提供者的大小、修改时间可能未知，只读或只写描述符可能是管道或 socket，写入模式的实现也可能不同。能打开 URI 不代表可随机寻址、排他锁定或得到长度。[ContentResolver 描述符](https://developer.android.com/reference/android/content/ContentResolver#openFileDescriptor(android.net.Uri,java.lang.String))、[文档大小](https://developer.android.com/reference/android/provider/DocumentsContract.Document#COLUMN_SIZE)

首版设计采用保守策略：以有界缓冲逐项读取 SAF 源到应用私有、受配额限制的发送快照，得到精确大小和摘要，再冻结该批清单。多目标共用准备结果，发送不再引用可变草稿或重新打开未知内容。准备阶段显示读取进度及临时空间需求，取消关闭流并清理本批快照。

读取前后核查来源标识、可用元数据和完整枚举结果。发现增删、长度变化、读取失败或授权变化就停止准备并要求重检。SAF 不普遍保证对正在被编辑的源提供一致版本；私有快照固定的是本次实际读取的字节，不能声称已经锁住源文件。提示“发送准备时读取的内容”，需要最新版本时应先在源应用保存，再重新准备。

该取舍增加一次源读取和私有空间，换取确定大小、后续字节稳定和多目标共享。配额不足须在发送前解释，提供减少内容或清理可放弃快照的入口，不自动切成来源不稳定的模式。以后可评估经过验证的本地可寻址源适配，但服务载荷仍重检摘要，不能仅凭文件名、大小或修改时间相信内容没变。

## 首次选择接收位置

首次启动显示“接收位置未选择”。用户可在设置先选，或在首个来件详情点击“选择保存位置”。没有有效目的地时自动接收不可用；打开系统选择器本身不接受来件。

完整目录接收默认使用用户明确授权、支持创建文件与目录且允许重读的**本地可写 SAF tree**。可提示用户在系统选择器中新建并选择 `Documents/Boardcast` 或 `Download/Boardcast` 子目录，但不代表已经授权。Android 11 及以后有内部存储根、受限制的 SD 卡根、`Download` 根、`Android/data` 和 `Android/obb` 的选择限制，不能引导用户授权受限位置。[系统目录限制](https://developer.android.com/training/data-storage/shared/documents-files#access-restrictions)

选中后核查实际读写 grant、目录创建能力、提供者、卷和位置身份。在该树中新建仅属于本次检查的测试文件与目录，验证写入、关闭、重读和清理，记录失败；不能只用 `DocumentFile.canWrite()` 判断，它可能因删除能力而返回 true。检查成功也不是未来写入的永久保证。[提供者能力](https://developer.android.com/training/data-storage/shared/documents-files#determine-operations)、[目录创建标记](https://developer.android.com/reference/android/provider/DocumentsContract.Document#FLAG_DIR_SUPPORTS_CREATE)

来件详情始终可查看提供者、保存层级和完整清单。“接受”前重检身份、有效接收开关、整个批次规则、目录权限及任务限额。换目的地产生新的确认结果，不能把旧目录批准悄悄用于新目录；设置草稿与暂停接收等即时动作分别提交。

## 本地位置与云提供者

系统选择器可能列出云提供者。选择时请求本地内容，并结合可查询 root 本地标记和经过验证的本地适配。`EXTRA_LOCAL_ONLY` 表示内容已在设备上，root 的 `FLAG_LOCAL_ONLY` 才表示内容操作不发网络请求，不能混同。[本地选择请求](https://developer.android.com/reference/android/content/Intent#EXTRA_LOCAL_ONLY)、[本地 root 标记](https://developer.android.com/reference/android/provider/DocumentsContract.Root#FLAG_LOCAL_ONLY)

首版默认接收与自动接收仅开放已确认本地的目的地。云端或无法确认本地属性时提示“此位置可能通过外部服务保存文件，请选择本地文件夹”，不开始写入。发送源也默认选择设备已有本地内容，不自动为局域网发送从云端取回文件。当前能离线打开的缓存不证明写入不会上传。

用户后来打开文件、分享给其他应用或开启系统目录同步，是另外的操作。邻间的直接传输不调用云账号或云上传，也不能控制用户后续开启的系统同步。未来云目的地须作为明确标明外部服务的独立导出功能，不改变默认“仅局域网”接收流程。

## 提供者能力与保存承诺

通用 SAF 的创建、重命名 API 不能直接等同 POSIX 原子 rename、Windows `CreateNew` 或全批事务。重命名还可能返回新的 URI，让旧标识失效；必须保存新返回值并重检。[新建文档](https://developer.android.com/reference/android/provider/DocumentsContract#createDocument(android.content.ContentResolver,android.net.Uri,java.lang.String,java.lang.String))、[重命名文档](https://developer.android.com/reference/android/provider/DocumentsContract#renameDocument(android.content.ContentResolver,android.net.Uri,java.lang.String))

完整目录接收至少需要稳定标识、可枚举父子关系、创建普通文件与目录、写入关闭后重读，以及安全处理任务自有未完成内容。关键能力缺失就在位置选择阶段解释，不先接受大批内容再等待不能完成的保存。

不依赖目标可 seek，也不假设大小、剩余空间可靠。随机块写入和恢复记录先在私有存储处理，最终顺序复制给提供者。root 可用空间字段可以未知，须显示“剩余空间未知”，不能造出足够或零空间。[可用空间字段](https://developer.android.com/reference/android/provider/DocumentsContract.Root#COLUMN_AVAILABLE_BYTES)

目标文档可能在复制未完成时已被系统文件程序看到。此时显示“正在保存”，重读校验后才计为已保存；不宣称每个提供者能隐藏半成品或实现跨文件原子提交。经验证的安全临时名称和重命名可以减少暴露，但 rename 标记本身不证明原子性或防覆盖。

## 名称保留与冲突映射

协议相对路径以 `/` 分隔，各段沿用跨平台校验：拒绝绝对路径、穿越、空段、`.`、`..`、非法字符、尾空格或点、NTFS ADS、Windows 保留名，以及大小写和 Unicode NFC 后的重复冲突。目录大小为零，文件大小非负，累计大小不能溢出，文件不能作其他条目的父节点。拒绝已知符号链接、重解析点、特殊文件与不能确认安全归属的结构。[协议文件安全](protocol.md#filesystem-and-approval-safety)

SAF 不提供可在任意提供者上替代底层链接检查的通用物理路径。首版只开放经路径、普通目录及父子关系验证的本地提供者；不从不透明 ID 猜链接，无法满足边界时明确不支持目录传输，不忽略条目后宣称完整。

保留原始合法名称。接收目录中已有同名内容时，为本批顶层项确定稳定数字后缀，例如 `项目资料 (1)`、`说明 (1).txt`；不与已有目录合并，不覆盖其子项。映射保存原相对路径、实际显示名、目标 document ID、父 ID 和 tree 身份，绑定发送者指纹、任务 ID 及清单，后续子项和合法恢复沿用。

防覆盖不能解释为“先查不存在，再创建，所以原子安全”。应用串行处理同一目的地内自己的创建，预查名称只帮助选择候选；之后只写提供者**新建返回的**文档标识，不打开按名字找到的既有文档。返回空值、复用已知既有 ID、实际名不合法、归属异常或并发冲突时停止该项，不以覆盖方式重试。

新建后立即记任务所有权，回读实际名和父级。提供者自动后缀满足安全、唯一且保持层级时可以作为本批实际映射并告知用户；截断、改扩展名或不能形成合法唯一名称时提示“此位置不能保留文件名称”，要求换位置，不静默接受。文件夹的实际映射确定后才创建子项。

外部应用和用户可同时改目的地，通用 SAF 没有全局排他事务。适配器通过新 ID、实际层级和重读结果检出可观察冲突；无法建立不覆盖保证的提供者不开放接收。验收须覆盖外部并发与各提供者命名规则，不能把单次成功变成通用承诺。

## 逐文件校验和提交

先验证身份、清单和当前许可，再分配私有暂存。每文件完整通过传输 SHA-256 后进入保存；目录条目按层级创建并确认，空目录无需等待载荷。

1. 在私有暂存核对字节数和摘要，不将网络块直接写到用户目录。
2. 按确定父目录映射新建目标，持久记录返回 URI、document ID 与所有权，再顺序复制完整文件；复制时显示“正在保存”。
3. 关闭写句柄后重开目标，完整读取并计算 SHA-256，核对精确字节数。写流返回成功、provider size 相同或暂存校验通过都不能替代这一步。
4. 目标摘要一致，实际名称与层级有效后，持久记录已保存，再增加计数。此后清理不再需要的暂存；恢复或授权中继若仍需内容，重读目标或保留有界缓存的策略须另行验收。

重读验证的是该时点可读取的最终字节，不等同任意提供者提供 fsync、远程同步落盘或全批永久持久化保证。目标不能重读、延迟可见、重读超时、hash 不一致或权限失效时显示“已接收，保存尚未确认”或“保存校验失败”，保留任务与合格暂存，不发成功回执。只在许可有效、任务未取消及有界重试范围内再核查，不永久后台重试。

空目录确认新 ID、目录类型、名称与父级，文件夹保存计数与文件计数分开。所有文件及目录都保存后才“全部完成”；字节 100% 后仍可能“正在校验”或“正在保存”。接收端完成事实不因最后回执丢失回退，发送端保留“回执未确认”。[保存与回执边界](protocol.md#negotiated-chunk-payload-and-recovery)

## 取消与清理

取消先持久记录状态、禁止新提交、停止工作者，再关读写句柄。清理正在保存项依据任务所有权；已保存文件、零字节文件与作为完成项保存的空目录保留，准确显示“已保存 X 个文件和 Y 个文件夹”。取消发送不能撤回对方已保存内容。

只按任务已记录 URI 与 document ID 清理未完成文档，不按名字、后缀或目录前缀扫描删除。标识属于本任务不等于永久删除许可；对象被外部改名、编辑或状态无法确认时保留并提示检查。

普通 SAF 不自动调用可能递归删除内容的接口清理父目录。仅当特定适配具备已验收的“只删除仍为空目录”条件删除能力，且目录由本任务创建、未作为完成空目录提交、没有已保存项时才允许清理。缺少该能力时保留空目录供用户在系统文件程序处理，不靠“检查为空后再删除”保证安全；用户后来放入目录的内容不会因任务清理被递归删除。创建返回前或所有权日志写入前发生故障，无法确认对象归属时同样不按名称猜测删除。

拔卷、占用、不能删除或 grant 撤销时保存待清理对象及原因。后续启动、卷恢复或重新授权先核查 ID 与所有权再尝试；重新授权不扩大删除范围。任务详情提供“查看未完成内容”，安全可行时提供“清理未完成内容”，删除失败不得显示清理成功。

## 中断与恢复能力

私有快照、暂存和保存未确认记录可保留本机事实，但不自动赋予网络续传。双方真正实现并协商 `chunks-v1`，且缓存重检和绑定有效后才开放“继续”；旧流式对端只“重新发送”，回执未知时提示先核查以免副本。[能力与恢复](protocol.md#negotiated-chunk-payload-and-recovery)

未来块任务至少绑定发送者指纹、传输 ID、内容 ID 与选定 tree 身份，不按文件名套旧缓存。继续前重检源内容或快照、规则、grant、目标映射、已保存目标与块摘要；不同内容或目的地不能继承旧授权。重启恢复暂停或待处理状态，由用户继续，不自动发送。

断线、停止、暂停按真实能力保留有效缓存；主动取消撤销继续入口并清理未完成内容。远端取消需 `receive-cancel-v1` 与原发送者认证，第三者不能猜任务 ID 清文件。完成、拒绝和取消清掉继续入口。七天过期和有界任务管理沿用项目原则；Android 实际配额独立测量，不把 Windows 默认容量当手机可用空间。

## 容量与存储失效

预检同时预算私有准备/接收暂存、目标最终副本、未确认副本和安全余量。多目标共用源快照；并发任务不能各自占用全部剩余空间。私有存储与目标同卷时合计开销，卷身份不明时保守预算。

已知不足在批准前解释所需空间；未知空间明确提示并依写入结果处理，不保证整批能保存。介质失效停止新写入，保留已提交文件及记录；只有观察到相应卷事实时才显示“USB 存储已断开”，不能把所有 provider 错误归因拔出。

私有空间不足、目标只读、目录移动、授权撤销与 provider 崩溃分别保留错误。换保存位置须重新确认并说明旧位置已保存部分，不隐性搬走或删除。打开实际 tree 或文档使用持有 grant 的系统入口；失败解释原因，不用猜测本地路径兜底。

## MediaStore 文件导出

MediaStore 可以用于明确选择的文件型便捷导出，例如把单独照片保存到图片集合，或把散文件另存到 Downloads 支持的集合。它不作为完整文件夹默认接收模型，不承诺独立空目录或任意树结构；目录批次用合格 SAF tree，不能为免选目录而平铺成媒体条目。

以后开放时注明“保存照片到图片”或“另存文件”，只处理适用内容。支持系统版本可用 `IS_PENDING` 管理未完成媒体条目，仍验证内容和实际位置。`RELATIVE_PATH` 是条目存放提示，不是物理路径，也不证明空目录已保存。[MediaStore 写入与位置](https://developer.android.com/training/data-storage/shared/media)

## 应用私有数据与设备身份

最终收件在应用之外的授权共享目录，内部只管理授权、设置、信任、任务、快照与暂存。应用专有数据在卸载时删除，不能用它作为默认最终收件位置；低空间可导致 `cacheDir` 被回收，因此需要恢复/确认的内容使用受配额管理的持久私有位置，不放预览缓存。[应用专有存储](https://developer.android.com/training/data-storage/app-specific)

未来目录职责示例，仅用于设计，不创建源码或实际目录：

```text
应用持久私有数据且排除备份
├── identity        公开证书和 Keystore 别名元数据
├── settings        本机设置及授权引用
├── trust           已核对设备与自动接收授权
├── drafts          顶层选择与明确排除
├── outgoing        准备快照和有界未完成发送记录
├── incoming        私有暂存和未来有效块
├── mappings        目标 tree 与已保存 document ID 映射
└── cleanup         未完成对象及清理状态

应用可回收缓存
└── previews        可重新生成的界面预览

用户授权的本地 SAF tree
└── 来件实际文件和原相对目录
```

身份设计以 Android Keystore 保护持久 P-256 私钥，完整证书 DER SHA-256 仍是跨端指纹。Keystore 密钥不可导出，但不能未经验证承诺每台设备有硬件保护。升级保留身份；重装、清数据、密钥失效须明确处理新身份。初始化异常停止宣称可接收，不静默换身份后沿用旧信任。[Android Keystore](https://developer.android.com/privacy-and-security/keystore)

身份元数据、信任与自动接收规则、URI 引用、任务映射和文件内容排除云备份与设备迁移，避免另一安装继承设备身份和许可。可使用 `noBackupFilesDir` 保存持久私有内容；适用版本还要分别定义备份与设备迁移排除规则，不能只凭 `allowBackup=false` 保证所有厂商都禁止迁移。新设备重选位置并重新核对信任，不以 URI 作跨设备恢复依据。[Auto Backup 排除与迁移](https://developer.android.com/identity/data/autobackup)、[备份中的 URI](https://developer.android.com/identity/data/backup#select-which-data-to-back-up)

## 存储验收矩阵

下列场景为实现完成条件，需在真实手机、平板、系统及 provider 上记录结果；协议 fixture 与回环测试不能替代 SAF、移动卷和跨设备验收。

| 场景 | 验收内容 |
| --- | --- |
| 文件与目录选择 | 两个系统入口、多选/取消、混合加入、重复来源与父子选择去重准确 |
| 完整层级 | 与 Windows 0.2.7 和 Mac legacy 双向传输；多级 Unicode、零字节文件、仅空目录结构正确，文件摘要相同 |
| 排除和不可读 | 排除与统计一致，失败项先阻止发送，明确排除后再准备，旧扫描不回写 |
| 名称和路径 | 顶层重名、保留名、尾空格/点、穿越、大小写/NFC冲突、溢出及文件作祖先明确拒绝 |
| 目录授权 | 未选择、受限根、合法子目录、重启、撤销、目录替换和重授权不越权 |
| provider 能力 | 本地/移动卷/云/未知、虚拟文档、未知大小、不可 seek、不能重读/删除及 rename 新 ID 处理准确 |
| 源内容变化 | 准备中增删编辑、临时授权失效与配额不足不漏传，任务用固定快照，多目标共享准备 |
| 保存完成 | 关闭后重读 hash，半成品不计保存；延迟可见、校验失败、回执丢失结果准确 |
| 冲突与并发 | 既有文件不覆盖、旧目录不合并，自动后缀及实际映射一致，外部创建编辑可安全停止 |
| 取消保护 | 第二文件保存中取消，只清 owned ID；已保存文件与完成空目录保留，后来加入目录的用户内容不删 |
| 容量和拔卷 | 私有/目标空间预算、未知空间、低空间与 USB/SD拔出处理正确，待清理与真实对象一致 |
| 恢复和许可 | 无块能力仅重新发送，未来恢复复核身份/内容/tree/映射/缓存，取消不留继续入口 |
| 身份和备份 | 升级指纹稳定、失效明确处理、备份迁移不复制内容和授权，新安装重新核对 |
| 系统文件程序 | 手机平板能查看实际位置，完成目录无包装层、校验 JSON 或块副本，卸载不删共享目录收件 |
