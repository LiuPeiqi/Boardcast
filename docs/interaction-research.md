# 交互调研记录

调研日期：2026-10-08。以下区分官方已记录行为、仓库反馈个案与本项目设计决定；不能将某个 issue 当成该产品在所有平台上的普遍现状。局域网发现和传输是本项目范围，不采用跨互联网传输、账号体系或云端中继。

## 保留 AirDrop 的优点

Apple 的使用说明把主流程压缩为选择内容、选择接收设备、接收方接受或拒绝；同一 Apple Account 的设备可自动接受。Mac 支持把项目拖入 Finder 的 AirDrop 页面。适合借鉴的是低学习成本、可见接收者和明确接受动作。本项目把“同账号”替换为用户明确建立的设备证书信任，不要求注册账号。

官方说明也记录了联系人模式、临时开放接收、设备需要 Wi-Fi/Bluetooth、VPN 可能阻断局域网等约束。现行 AirDrop 可在离开附近范围后通过互联网继续传输；本项目明确不采用这一行为。

来源：[Apple AirDrop 使用说明](https://support.apple.com/guide/iphone/use-airdrop-to-send-items-to-nearby-devices-iphcd8b9f0af/27/ios/27)、[Apple iPhone/iPad AirDrop 支持](https://support.apple.com/en-lamr/119857)。

Apple 的安全说明描述了 BLE 发现、点对点 Wi-Fi 与 TLS，并区分已验证身份和未验证设备名。对应本项目：设备名用来辨识界面，证书指纹用来辨识身份，两者不可混为一谈。Apple 的文档涉及自有生态和 iCloud 身份，因此不是可直接搬用的开放跨平台协议。

来源：[Apple AirDrop security](https://support.apple.com/en-ca/guide/security/sec2261183f4/web)。

## 界面决定

当前 Windows 发送页以待发送内容和附近设备两列完成常用流程，导航区显示本机名称与局域网状态。2026 年 10 月 9 日的操作精简已进入源码：附近设备标题、分组选择、显示数量和刷新共用一行；空文件清单通过可点击箭头和提示添加，非空清单在标题行显示添加与清空；移除、文件夹排除、展开清单与搜索按需出现。筛选无结果时点击提示清除筛选，不改变实际发送来源。这些变化已纳入 Windows 0.2.6 签名发行；分发状态与验收结果见 [签名发行说明](signed-release.md)。

设备行优先使用本机备注，身份仍由证书指纹识别。Windows 0.2.6 最终采用单行设备项：勾选、平台图标、名称、必要的警示状态图标与版本。灰色为实际运行版本，蓝色为该设备可提供的适用更新版本，点击查看更新详情；不另设“有更新”气泡。分组、系统文字、地址和信任等信息进入帮助提示、辅助名称及详情，对端原名在详情核查。Mac 延续这一密度并提供键盘可达的完整详情；首阶段补版本兼容解码后只显示灰色信息，Mac 更新链路完成前不显示蓝色入口。高频选择和发送不经过配置页面，信任、个人分组和自动接收许可进入设备详情。

接收请求应展示发送者、内容概览、文件数、大小、保存目的地及明确接受和拒绝动作。当前 Windows 请求卡只展示前八个清单条目与剩余数量，首页接收路径在打开目录按钮的提示中；Mac 方案补完整清单入口和常驻实际接收位置。顶层所选项数与包含子目录的清单条目数分开命名，避免两端统计含义不一致。辅助摘要不替代清单和身份，也不提升信任。

未发现设备时区分服务状态、局域网开关、筛选和可观测的连接错误，不能由空列表推断对方离线或权限拒绝。手动局域网 IP 是发现受阻的恢复入口；Windows 已有实现，Mac 需要移植。路径失效、权限失败、磁盘不足和中断保留在相应任务中，不能只用短暂提示承载。

视觉继续以网格、留白、少量功能性色彩和清楚字级组织内容，避免装饰仪表盘、持续动画和重复工具栏。Windows 使用原生窗口、托盘、系统面板和常见快捷键；Mac 使用原生窗口、菜单栏、Finder 拖放、文件面板、语义颜色和平台快捷键。共享产品语义，平台布局根据可用空间和操作习惯调整，详细规格见 [macOS 产品与界面设计](macos-design.md) 和 [Mac 本地开发交接](../platforms/macos/DEVELOPMENT.md)。

这些为设计决定，不是已通过可用性研究验证的结论。对应验收包括两台 Windows、Windows 与 Mac、网卡变化、休眠恢复、同名并发、长名称、大目录、部分完成、磁盘不足和防火墙阻断；记录内容摘要、最终目录、传输速率、空闲 CPU/内存及失败恢复时间。Mac 原生构建、权限、UI 和双机验收仍需在 Mac 完成。
